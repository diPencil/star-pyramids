# Top Tours horizontal slider

Owner request, 2 November 2026: Explore Egypt's Top Tours must be a moving horizontal slider on desktop and mobile instead of multiple card rows.

The homepage reuses the existing HorizontalSlider and TourCard. Scoped styles show four cards on large screens, two at widths up to 1024px, and 86% cards with a next-card hint at up to 760px. Native touch/trackpad scrolling and scroll snapping work without cloning records. Cards, links, prices, favorites and image galleries retain their existing owners. Other homepage sections remain unchanged.

Owner revision, 2 November: Top Tours always includes the full published database catalogue, without applying the legacy featured selection/limit. Drafts remain excluded by the shared resolver. CMS title, subtitle, visibility, order and View All link remain authoritative; other sections retain their existing selection/limit rules. The old number represented scroll positions rather than tour count.

Latest owner revision, 2 November: replace five-second steps with continuous infinite movement at 40px/second. The existing grid cards are recycled using CSS order and a bounded native scroll offset, without cloning records, duplicating interactive controls or scrolling backwards to the start. Animation uses requestAnimationFrame and elapsed time, not an interval; no React state updates occur per animation frame. Two EN/ES/IT-labeled, 44px arrows sit on the left of one footer row, with the CMS View All action on the right. There is no counter, dot navigation, playback button or visible scrollbar. The focused track supports Left/Right/Home/End without intercepting keys from card controls. When everything fits, View All remains right aligned without unnecessary arrows; an empty source creates no empty carousel region. If there is not enough overflow to recycle a whole card, the small collection remains manually scrollable instead of manufacturing duplicate tours.

Mouse hover pauses continuous motion, and leaving resumes on the next frame without a five-second wait. Arrow clicks animate one card over approximately 350ms, even while hovered, then continuous motion resumes when the interaction ends. Pointer-origin focus does not latch a permanent pause; keyboard focus still pauses to keep links stable. Touch gestures do not create sticky synthetic mouse hover. Wheel/touch gestures cancel an ongoing arrow animation; native drag position is adopted on resume. Reduced motion disables automatic movement and makes manual movement instant; hidden/offscreen content does not accumulate a catch-up jump. Resize observers remeasure card widths, and cleanup restores prior card order styles and removes animation frames/listeners. Other related-tour/video sliders retain interval navigation, appearance, dot controls and optional playback support.

Verification uses mocked component effects/geometry, real homepage server markup in EN/ES/IT, CSS breakpoint contracts and existing tour discovery/recommendation/template regressions. No browser/device testing, database writes, schema, pricing, dependency installation or deployment is involved. The 21st UI Build instructions and existing design context were consulted; no 21st CLI/connector was available. Reused the installed project component instead of downloading a new one.

Rollback: remove the featured section slider wrapper/import/styles and restore its grid; revert the shared slider interaction changes if required. No data rollback is necessary.
