# Homepage Trip reviews submission

Owner request: the homepage Trip reviews Write a review action must open an internal modal, require selecting a trip, and feed that trip's review section and the homepage after normal moderation.

## Cause and implementation

ProviderReviewsSection previously allowed internal writing only for All/Website; Trip reviews fell through to the external-provider branch and displayed a disabled unconfigured-link button. The existing review API already supports tourSlug, requires an authenticated account, rejects unavailable/unpublished tours and duplicates, and stores PENDING for staff approval.

Trip reviews opens the same ReviewWriteModal with a required trip choice. The selector reads the public lightweight /api/tours list with no-store, accepts unique explicitly published records only, and sends the selected canonical tourSlug through the existing POST /api/reviews. It cannot silently fall back to @website. Labels, loading/error/retry/empty messages support EN/ES/IT. Arabic remains disabled.

Owner refinement: the original native select grew to the longest tour title and offered no visible search or category context. ReviewTripPicker now uses the project's existing inline combobox pattern, without a portal or native popup. Type part of a trip name, optionally filter by the four stored categories, then explicitly choose a result. Each result and selected summary show the localized actual category, not a guess from the tour name. Unknown categories are labeled unavailable. Results use bounded internal scrolling (up to 220px/28dvh), long titles wrap within the modal, and choosing a result collapses the list. Editing the search/filter clears the old selection so free text cannot silently submit a different trip. Keyboard arrows/Enter select; Escape first dismisses results without bubbling to the parent dialog. The public endpoint already returns category; no API/schema/database change is necessary.

Failed submissions preserve typed text and selection. A 401 offers login with a return URL to the chosen tour's reviews. Failure/retry/empty catalogue states never create fake choices or report local success. Existing Website/All website-review behavior and external-provider URLs remain unchanged. Tour detail forms retain their fixed canonical tour; they do not gain an unnecessary picker.

The same approved review is returned by scope=trips, scope=all and tourSlug=<chosen-trip>, and excluded from scope=website and other trips. No published count or rating is incremented on pending submission. Trip review cards use the trip icon. Both homepage and tour-detail public feeds refresh on visible/focus return so staff moderation can be read after returning to the page. Tour-detail refresh is deferred while its writing form is open, preventing a reload from unmounting typed content. Tour requests explicitly use no-store. This is foreground revalidation, not polling or a push notification service.

## Verification and boundaries

Compact-dialog refinement: scoped review-only CSS reduces the card to a preferred 440px, padding to 16px (14px on phones), heading/context/form gaps, a 96px initial textarea and a 144px/20dvh result list. Category filters use five columns on wider screens and three below 480px; long labels/titles still wrap. Inputs retain 16px text to avoid mobile focus zoom, and interactive controls retain 44px targets. Only review-dialog geometry overrides global Appearance sizing; published colors/font families and all other page forms remain owned by their existing settings. Modal max-height and internal scrolling remain available; no transform scaling, hidden fields, truncation of review text or submission/validation change is introduced.

Repeated empty-message repair: WebsiteReviews and ReviewWriteModal previously shared the same sibling React key (`all`, `website` or `trips`). Opening the dialog introduced a duplicate identity, allowing reconciliation to leave stale feed DOM after closing. Their keys now use distinct `local-reviews:` and `review-form:` namespaces; the feed key stays stable while toggling the dialog. A regression test failed on all three local scopes before the fix and passes through ten open/close cycles per scope afterward. This addresses the identity collision without concealing empty messages, clearing real data, forcing repeated feed remounts or changing moderation.

Tests cover the enabled Trip action, selection requirements, duplicate/private choices, real submission body, preserved text on authentication/network failure, retry, existing website and tour forms, and an in-memory POST -> moderation -> homepage/tour GET flow (including rejection). No real database is used by these tests. Existing moderation, authentication, duplicate/rate-limit/origin checks and schema are unchanged. No public or production review was created, approved, modified or deleted during implementation; no browser automation is used. Pixel/device interaction verification remains unperformed under project rules.
